KINDRED — EXTERNAL SETUP AND CREDENTIALS

This pack contains no working secrets and creates no external accounts. Cursor should keep docs/INTEGRATION-SETUP.txt current as it verifies exact provider settings.

LOCAL DEMO
Requires the chosen Node.js version and package manager. Runs through explicit fixtures without cloud credentials. Persisted UI drafts/preferences are acceptable locally. Demo operation is never live acceptance evidence.

DATABASE AND SIGN-IN
Create a development Supabase project or use a supported local Supabase environment. Configure project URL, publishable key, server database connection, callback origins, email login behavior, and private storage. The publishable key is not an admin credential. Keep service-role/admin keys server-only and use them only if required. Record migration ownership and connection pool constraints. Set up a separate production project before a production launch.

GITLAB
Register a development OAuth application with the exact callback URL generated by the implementation. Use an account and disposable project authorized for testing. Verify required API scopes against the actual implemented operations; explain any broad scope. Use a separate credential-encryption key and rotation/version strategy for stored connection credentials. Configure webhook authentication when used. Disconnect/revoke must be supported. Application login and repository authorization are separate concerns.

BACKGROUND EXECUTION
Configure an Inngest development environment and the actual required event/signing keys for the installed SDK. Document public callback endpoints where needed. Provide a way to run and inspect the worker locally. Never expose unsigned privileged job endpoints on a public deployment.

SANDBOX
Configure the Vercel account/project/team identity and the authentication mechanism supported by the current Sandbox SDK. Verify supported runtime limits, egress controls, cleanup, preview access, and cost. Do not treat a private preview URL as equivalent to authorization unless the provider guarantees it. Start with disposable repository data and no production secrets.

MODEL
Configure an Anthropic server API key and a currently supported tool-capable model identifier. Verify account access and pricing. Keep provider tokens in the model integration service, not in repository code or browser storage. Define per-run token/step bounds and record actual reported usage.

DEPLOYMENT
Associate a development Vercel project with the authorized test repository or supported direct-deploy flow. Verify team/project IDs, token permissions, callback origins, production-branch behavior, and promotion/rollback capability. Ensure Git pushes do not silently bypass Kindred's owner approval by triggering automatic production deployment. Preview deployments and production promotion need explicit policy.

LIVE PILOT
Use separate environments and credentials; verify backups and restore; configure monitoring/retention and limits; run the acceptance script with a disposable project. Human approval of infrastructure setup and production launch is separate from implementing code. Do not paste secrets into Cursor chat; configure them through environment files excluded from version control or the hosting provider's secret manager.

ENVIRONMENT MANIFEST TO GENERATE
For each actual configuration key: exact name, purpose, public/server-only classification, development source, production source, required stages, validation behavior, and rotation owner. Verify names from current SDK docs rather than inventing variables in this pack.
